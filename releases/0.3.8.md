# Runcell Desktop 0.3.8

Runcell Desktop now provides Windows x64 NSIS installers and Linux glibc x64/arm64 AppImage and Deb packages, alongside macOS arm64/x64 DMG and ZIP files. Bundled RunCell remains 0.2.9.

Desktop source: 2026-10-29, [feat(release): support Windows and Linux desktop packages (#7)](https://github.com/ObservedObserver/runcell-desktop/commit/36d647c4af6c8003a19b11e4bea09ce155db8e3d).

## Installation and updates

Windows installs per user and allows choosing the installation directory. This release has no Windows signing certificate, so the installer is unsigned and Windows may show an unrecognized-publisher warning. Windows NSIS and Linux AppImage support application updates, with installation after an explicit restart action. Deb installations provide a link to download the latest package. Existing macOS Squirrel update feeds remain compatible.

Linux packages are built and tested on native Ubuntu 24.04 runners. For Ubuntu, the Deb package is tested with normal application launch flags. AppImage needs the host distribution to permit Electron's user namespaces. Extracted AppImage acceptance under Xvfb explicitly disables Chromium sandboxing because of the runner's AppArmor policy; that does not establish compatibility with every distribution's default policy. Older distributions, Windows arm64 and Linux armhf are not covered by this release validation.

AppImage prepares a verified persistent Python interpreter when creating the first managed environment. Environments reference that copy instead of a temporary AppImage mount, so changing the mount path does not recreate an environment or discard its installed packages. Copies remain under the app's user-data directory for environments that still use them.

## Validation

Local `yarn check:all` passed lint, adopted formatting, source/test types, 383 TypeScript tests, 10 release-publisher tests and 33 development-tool tests. Three opt-in tests were skipped in the fast lane. A local Grok probe fixture once hit its short startup deadline under the full test load; its focused rerun and subsequent full checks passed.

`yarn package` and its package audit passed. The packaged macOS client verified actual main/preload/renderer identity and the bundled source revision, prepared an offline environment, and started/stopped real Jupyter. The complete Electron suite and both real Jupyter integration tests passed after the final shutdown change.

[Final PR CI](https://github.com/ObservedObserver/runcell-desktop/actions/runs/40831197385) passed macOS Electron/development/Jupyter checks and all native package jobs. Windows acceptance installed NSIS into a disposable directory, audited the installed app, checked the x64 executable, and exercised the packaged IPC/runtime/Jupyter flow. Windows Jupyter integration also verified that owned kernel processes exited before fixture removal. Linux acceptance checked native ELF architecture, launched extracted AppImage, relocated it and verified that an added Python module survived, then installed and exercised Deb with normal application launch flags.

The first Linux arm64 attempt timed out waiting for the renderer on the second AppImage launch. Rerunning the same commit passed the complete acceptance without changing assertions. The cause of that transient startup timeout was not isolated; both attempt logs remain in the CI run.

All client scenarios use marked synthetic profiles with Code Agent providers disabled. No live model requests, production profiles, provider sign-in flows, or upgrade from an older installed desktop release were exercised. The existing dependency `eval`, large-bundle and experimental SQLite warnings remain.

## CI follow-up

A later source CI run exhausted the Linux x64 runner filesystem, reaching 7 MB free and exiting before its first renderer. [The CI follow-up](https://github.com/ObservedObserver/runcell-desktop/pull/8) removes verified, audited staging copies before installer acceptance and requires at least 3 GiB free. It also keeps one Xvfb display alive across the three Linux client scenarios, limits crash core files, records failed-client diagnostics and canonicalizes paths for local mounted-image checks.

[Final follow-up CI](https://github.com/ObservedObserver/runcell-desktop/actions/runs/40980171689) passed quality, macOS Electron/development/Jupyter checks, Windows installed-package acceptance, both Linux architectures' AppImage relocation and Deb acceptance, and the required-check gate. The arm64 job recorded 25.4 GiB free after staging cleanup and passed all three client scenarios. This follow-up changes CI and test helpers; the published 0.3.8 application remains the verified release from the desktop source revision above.
