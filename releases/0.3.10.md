# Runcell Desktop 0.3.10

Runcell Agent now connects notebooks automatically when you send the first task.
You no longer need to open JupyterLab before asking the Agent to create or run a
notebook. The Agent page stays visible while the notebook works in the background.
If notebook startup fails, the task is not submitted and you can retry.

## Validation

A new desktop profile signed in normally and selected an empty project. Without
opening JupyterLab, a real GPT-6 Sol task created `first_task.ipynb`, executed a
Python cell in the notebook kernel and printed `RC0310_RESULT=385`. The
kernel-created `first_task_result.txt` contained the same result. There were no
tool failures or execution fallback notices. Backend authentication, actual
provider usage and credit receipts were correlated.

This test used the real desktop development client, local website/Auth/backend
services and an external model provider. It did not use synthetic responses or
production credentials. It does not establish every model/provider or hosted
production authentication path.

The bundled RunCell version remains 0.2.10, with a revision-stamped notebook
connection patch from source `92f1d64944421311d30fdde4aab213ddc03404a6`.

## Published package acceptance

The stable [0.3.10 release](https://github.com/runcell-ai/runcell-desktop/releases/tag/v0.3.10)
was published from source `388fb6b37da4a9c8f1248d979906d7e04e4817c7`.
Both macOS architectures passed Developer ID signing, Apple notarization,
stapling, Gatekeeper verification, and real packaged desktop/offline Jupyter
acceptance. Windows x64 NSIS and Linux x64/arm64 AppImage and Deb packages
passed actual installation and execution checks. Windows installers are unsigned.

The release contains 17 assets, including update feeds. All 10 artifact sizes
and SHA-256 digests in the downloaded
[release manifest](https://github.com/runcell-ai/runcell-desktop/releases/download/v0.3.10/manifest.json)
match GitHub's uploaded asset metadata.

During release, macOS 26 ARM runner capacity and Intel signing/network failures
required moving CI/release jobs to supported macOS 15 runners. Linux ARM had
an initial renderer startup timeout; the unchanged-source retry passed. Linux
runner cache cleanup and disk/inode checks were also strengthened. No acceptance
assertion, timeout, signing or notarization requirement was relaxed.

See [0.3.8 platform notes](https://github.com/runcell-ai/runcell-desktop/blob/main/releases/0.3.8.md)
